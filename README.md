# commenter

Комментарии для постов **MAX-канала** (нативных комментов у MAX нет). Открывается
как мини-апп по кнопке «💬 Комментарии» под кросспост-постом (бот вешает кнопку
`OPEN_APP`/`LINK`). Цель — фича PRO-тарифа бриджа MaxTelegramBridgeBot.

Фишка — **кросскоменты**: единый тред между Telegram (комменты в привязанной
дискусс-группе канала) и MAX.

## Структура

```
commenter/
  backend/    — Go (stdlib), HTTP API + раздача мини-аппа. MVP: in-memory store.
  frontend/   — Vue 3 + Vite, мини-апп (тред + форма коммента).
```

## Запуск (dev)

```bash
# бэкенд (:8090)
cd backend && go run .

# фронт (:5173, проксирует /api на :8090)
cd frontend && npm install && npm run dev
# открыть http://localhost:5173/?post_id=test
```

## Прод-сборка

```bash
cd frontend && npm run build         # → frontend/dist
cd ../backend && go build -o commenter .
STATIC_DIR=../frontend/dist ./commenter   # раздаёт мини-апп + API
```

## API

- `GET /api/comments?post_id=<id>` → `{ "comments": [...] }`
- `POST /api/comments` `{ "post_id", "text" }` → созданный коммент
  (личность автора — из подписи мини-аппа, заголовок `X-Init-Data`)

`post_id` = ключ поста, напр. `"<maxChatID>:<maxMid>"`.

## Что подтвердить по MAX (блокеры до боевого запуска)

1. **`OPEN_APP` под постами канала** — работает ли мини-апп-кнопка под постом
   канала (а не только в ЛС бота)? Если нет — фолбэк на `LINK` (обычный браузер/вебвью).
2. **Авторизация мини-аппа** — есть ли у MAX подпись `initData` (как Telegram
   WebApp), чтобы достоверно знать `user_id` комментатора. Сейчас `auth.go` —
   заглушка («Гость»).
